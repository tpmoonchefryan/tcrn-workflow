# TCRN Workflow 0.11.3

`0.11.3` is the STORY-189 switch-window serving release: the engine CLI now
serves a chain from Postgres when `TCRN_PG_CONNECTION` and `TCRN_PG_SCHEMA` are
set, so the facade can answer reads for the five PG-backed chains after the
file→pg migration. Cut on top of `0.11.2` with `3e7ae34`.

## The changes

- **The engine CLI reads a chain from Postgres when configured.** The read
  verbs previously materialized the file tree unconditionally. `runCli` now
  arms the storage and store backend factories with a `PgBackend` /
  `PgStoreBackend` for the schema named by `TCRN_PG_SCHEMA` when
  `TCRN_PG_CONNECTION` is also set, so `status`, `work-list`, `validate` and the
  other workspace-touching verbs answer from the PG chain. The migration verbs
  are excluded — they carry their own explicit backends, which
  `resolveBackend` prefers — and `commands` is excluded because it answers from
  the catalogue, not a workspace.

## Compatibility

- No verb, event-schema, storage-version, or file-backend byte change. The CLI
  verb count stays 104.
- A chain migrated and verified green under `0.11.1`/`0.11.2` re-reads green
  from Postgres with the env set; the file tree remains the read source when the
  env is unset (no behaviour change for existing file-backed invocations).
- Release hygiene unchanged: all five manifests, `FRAMEWORK_VERSION`, and the
  `P8_VERSION` / `P8_TAG` constants are cut on one version. Carries an
  annotated tag.

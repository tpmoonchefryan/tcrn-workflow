# TCRN Workflow 0.10.2

`0.10.2` is a patch release that completes **WSA-3**. `0.10.1` admitted the rule
on the transition path — an Initiative may not close while its subtree still
holds live non-terminal work — which guarded the closing instant and only the
closing instant. Creating a fresh child under an already-done Initiative stayed
legal, so a closed subtree could be reopened one `work-create` later and `done`
stopped meaning finished. `0.10.2` mirrors the admission on the create path.

## The change

- **Before (0.10.1):** WSA-3 in `transitionWork` only. `createWork` accepted a
  new non-terminal record under a `done` Initiative, measured on a live chain.
- **After (0.10.2):** `createWork` refuses a non-terminal record whose parent is
  a done, non-tombstoned `Initiative` (`WORKSPACE_INPUT_INVALID`). The identical
  create under a live Initiative is still accepted, so the rule discriminates on
  the parent's state rather than refusing every child.

The check lives in the mutation reducer — the write path's input-validation
point, which `appendEvent` runs once against claim-fresh state — and **not** in
`validateWorkGraph`. Replay runs that validator over every historical event,
which is precisely how `0.10.0` fail-closed an existing chain; placement, not the
rule, was that defect.

## Release hygiene fixed here

`0.10.0` and `0.10.1` were both cut while the four package manifests disagreed:
the root said `0.10.x` and `packages/{cli,core,protocol}` still said `0.9.0`, so
`verify:p8` could not pass and did not run. `0.10.2` brings all four manifests,
`FRAMEWORK_VERSION`, and the `P8_VERSION` / `P8_TAG` constants onto the same
version, and is tagged with an **annotated** tag — the helper's `IDENTITY` pins a
tag object, which the lightweight `v0.10.0` / `v0.10.1` tags never provided.

## Compatibility

- No verb, event-schema, or storage-version change.
- `PROTOCOL_REASON_CODES` is unchanged; the new refusal reports
  `WORKSPACE_INPUT_INVALID` from the core layer.
- Chains are byte-identical across 0.9.0 / 0.10.1 / 0.10.2 — this patch adds a
  write-path admission, not event bytes.
- Existing chains that already hold live work under a done Initiative stay
  readable: the rule admits new writes and never runs on replay.

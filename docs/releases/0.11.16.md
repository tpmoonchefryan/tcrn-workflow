# 0.11.16

A clean install of 0.11.14 left five things behind, and nothing noticed: the
host wiring stayed one folder deep, one host had no helper skill at all, three
launchd timers vanished, the deployed engine fell behind its own release, and
an MCP face went unregistered. The lesson of this release is that an install
surface kept in prose is an install surface that leaks. So the surface is
engine data now, and the doctor executes it.

## The install manifest

`install-manifest` is a read-only verb that enumerates every wiring item the
platform expects, across both adapters, whether or not the current host is the
one being wired. Each item carries four load-bearing fields: the layer
(machine, container, or project), a placeholder-only path template, the writer
(engine adapter, the host itself, or a guided human step), and an acceptance
probe. The required-item catalog is a separate literal, not a projection of
the item list — deriving one from the other would make the completeness
predicate tautological, which is precisely the bug an earlier revision had and
the mutation suite now guards against: delete any item, rebuild, and the gate
goes red.

## A doctor that runs the probes

The platform doctor now executes what the manifest declares instead of keeping
its own private list. Wiring presence, deployment freshness against the helper
pin, helper copies compared by digest rather than by existence, launchd duty
judged by last exit status and product freshness rather than by registration,
hook targets resolved and stat-ed under the container root, bridge files parsed
for reference syntax, and trust-archive freshness against the deployed engine.
Each leg has a synthetic red in the suite, because a gate that cannot go red is
not a gate.

Two of those legs were paid for in findings. The hooks leg exists because a
container-root settings file shipped four hook registrations that resolved to a
path that did not exist — every hook silently dead while the old check reported
the file present. The launchd leg judges outcomes because a backup timer ran
for two days with exit status 1 while the old check reported it on duty.

## Backups that admit failure

The paired backup died structurally when the platform relocated: the remote
half was vacated, the local pair mode was deliberately retired, and the
scheduler kept firing into a refusal. It is replaced by a local snapshot timer
— tar, sha256, recorded chain versions, fourteen-copy rotation — and an
encrypted pure-file offsite leg that pushes to dumb storage and verifies the
readback byte for byte. Both are manifest items with freshness probes, so the
next stall is a red check, not a quiet absence.

## Evidence residency and cross-repo privacy

Originals that carry real machine paths live in the platform archive outside
any repository; the public evidence copies are sanitised transcriptions that
say so in their first line. A new cross-repo privacy gate walks every governed
project root the manifest names — including the ones that never had a gate of
their own — and fails on absolute home paths and private identity markers. It
exists because install receipts with real paths were found sitting untracked
in four public repositories, one `git add -A` away from history.

# TCRN Workflow 1.2.1

This patch release makes write-time conflict detection and `--supersedes` the
only way knowledge retires (Owner ruling TCRN-CROSS-MIN-225,
TCRN-CROSS-STORY-465). The command catalog and the replay snapshot format are
unchanged from v1.2.0, and the records this release stops writing stay
readable as history. Upgrade the Claude Code and Codex hosts together; see
"Upgrading".

## Knowledge retirement

- Knowledge retires automatically only through write-time conflict detection
  and `--supersedes`. `maximumAgeDays` still only marks a card stale, and a
  full store refuses the next write rather than evicting a card (Owner ruling
  TCRN-CROSS-MIN-225 D1 and D4).
- `retire-sweep` retires nothing for any instant, window or telemetry and
  writes nothing, the marker's `lastSweepAt` included. It answers
  `KNOWLEDGE_RETIRE_SWEEP_CONFLICT_ONLY` under
  `tcrn.knowledge-retire-sweep.v2` (TCRN-CROSS-SUB-258).
- Fitness is a read-only statistic, `tcrn.knowledge-fitness.v2`: per artifact
  it counts every readable telemetry record up to `--at`, with no window,
  eligibility or proposal. `retire-proposals` returns those counts with the
  retired cards and their historical retirement records, and its `proposals`
  and `ruleDiffs` are always empty. `--window-days` and `--min-events` are
  still validated, are listed back under `retiredInputs`, and have no effect.
- `fitness.windowDays` and `fitness.minEvents` are retired settings: a new
  write is refused with `SETTINGS_KEY_UNREGISTERED`, and a recorded value and
  a recorded removal both read as history (TCRN-CROSS-SUB-258,
  TCRN-CROSS-INC-389, TCRN-CROSS-SUB-261).

## Observation records

- The hooks and the batch entry no longer write observation boundary rows,
  per-channel or four-channel seal receipts, `collector-self-check` records or
  `telemetry/summaries/<day>.json`, and SessionStart no longer runs the
  retirement sweep (TCRN-CROSS-SUB-257). The four channel events keep their
  payloads.
- Three reason codes answer the retired entry points, and none of them writes
  anything: `TELEMETRY_BOUNDARY_RETIRED` for `--observation-boundary` passed
  to `knowledge-inject.mjs`, `TELEMETRY_SELF_CHECK_RETIRED` for a legacy
  `selfCheck` call to the batch verify emitter, and
  `TELEMETRY_OBSERVATION_RETIRED` from `telemetry-observation`, which keeps its
  catalog entry, validates its arguments and then refuses without reading the
  workspace or telemetry.
- Records already written stay readable and change no fitness count or
  retirement result: boundary rows, receipts, self-checks, day summaries,
  `lastSweepAt` and `tcrn.knowledge-retirement.v1` records. `telemetry-list`
  and `telemetry-stats` read them as before, and the `countsByKind` of
  `telemetry-stats` still counts historical boundary rows under their kind.

## Settings and replay

- Replay reads a `settings.removed` event for a retired key as history: its
  envelope checks (exact fields, field types, a strict and event-bound
  timestamp) still apply, and it neither consults nor changes the current
  settings. Removing a live key that was never set is still
  `WORKSPACE_EVENT_CORRUPT` (TCRN-CROSS-INC-389, TCRN-CROSS-SUB-261).
- A replay snapshot is still verified exactly as stored, and only its seed
  drops retired keys, so no retired key is carried into the current settings
  and the snapshot-seeded read and a replay from genesis hold the same state.

## Portal

- The evolution panel lists conflict retirements only: each card a
  `--supersedes` write replaced, with its replacement and time, newest first,
  and its fourth stat counts them. The window, last-sweep, proposal and
  pending-retirement lines are gone, and neither the evolution nor the
  knowledge view calls `retire-proposals` any more (TCRN-CROSS-SUB-259).

## Upgrading

- Upgrade both hosts together. An installed 1.2.0 hook keeps writing the
  historical formats (boundary rows, receipts and self-checks) until its host
  is upgraded; 1.2.1 reads them as history.
- A workspace whose newest replay snapshot was taken while a now-retired key
  (`execution.personalessDispatch`, `model.economyTier`, `fitness.windowDays`
  or `fitness.minEvents`) was still live, or that recorded such a key while it
  was live and also holds another setting, conference, gate or template
  record, may first answer `WORKSPACE_VIEW_STALE` from `validate` and the read
  verbs that check the views after the upgrade. Upgrade every engine copy that
  reads the workspace together, then run `snapshot-replay-rebuild` and after
  it `recover` with 1.2.1.

## Known limitations

- A Codex knowledge judge call that times out or fails to spawn is recorded
  with `reasonCode` and `model` only, without `cliSource` and
  `failureDetail`; the v1.2.0 statement that judge telemetry carries both
  fields does not hold for these two cases (Owner ruling OQ-S4-1 A).
- The Claude host knowledge judge stays off (Owner ruling OQ-EC-1 C), and its
  calls are recorded as `UNINJECTED_MODEL_AUTH_UNAVAILABLE`. A hook process
  does not receive the host CLI path, so a judge record written from a hook
  carries `cliSource` `path`. A host-probe run outside a host session falls
  back to `claude` from `PATH`, and its `command[0]` is then the bare name.
- `release:preflight` reports a rejected release commit
  (`RELEASE_COMMIT_SHAPE_INVALID`), the other release tag check failures and a
  failure inside the P8 release module as `TASK_INTERNAL_ERROR`, carrying only
  the error message. The checks still fail closed.
- The portal's evolution panel lists at most the newest 240 conflict
  retirements; its stat counts all of them.
- `telemetry-observation`, `--window-days` and `--min-events` remain only to
  keep the command catalog compatible.

## Proof budget

Since 1.2.0, under Owner ruling minutes:1e37408180449980244bdf7b D1 (a reached
cap is raised to the measured value in the landing commit, with no margin),
`hardRatio` rose from 2.5354 to the measured 2.5481 (TCRN-CROSS-SUB-258) and
then to the measured 2.5521 (TCRN-CROSS-SUB-261), with two recorded
exceptions (63 to 65). `coreSourceLineCap` fell from 24683 to the measured
23943 (TCRN-CROSS-SUB-258) and rose to the measured 23956
(TCRN-CROSS-SUB-261). `verifyScriptCap` 14 and `claimCap` 9 are unchanged.
The proof-to-product ratio is 72390/28365 = 2.5521, equal to the hard ratio.

The commit the v1.2.1 tag names changes only release metadata, the release
commit shape `release:preflight` checks (TCRN-CROSS-INC-093);
`FRAMEWORK_VERSION`, the P8 release identity, the README version and the
test pins moved to 1.2.1 in the commit before it.

The immutable v1.2.0 Engine and v1.0.6 Helper publications remain unchanged.
This release is published only after exact-commit CI succeeds and its tags,
assets, bootstrap, and downloaded digests are independently verified.

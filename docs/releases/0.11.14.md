# 0.11.14

A workspace can now say which model each host should drive, per named
configuration, with one default per host and per-persona pins — and the
independence a review claims is checked at the moment it is claimed.

## Execution configuration

A model choice is a composite judgement of cost, intelligence and feel: when
Opus 5 shipped, a real population rolled back to 4.8, and both releases sit in
the same capability tier. So the engine records the model NAME the user chose
and never interprets it, exactly as it treats a backup destination. What it
does own is referential integrity: a `default` must name a configuration that
exists, and removing a configuration something still points at refuses with
`EXECUTION_CONFIGURATION_IN_USE`.

Two layers, ruled deliberately. Host configurations are named entries
`{name, model, note?}` for a closed host set — `claude-code` and `codex`,
exactly the adapter families that exist. The `default` pointer makes a global
rollback ONE switch, and it is called `default` rather than `active` because a
pinned persona does not follow it: `persona-binding-set` keeps a reviewer on
the strong model while the default moves. Each action is its own chain event,
so "the default moved" is one legible line in the audit trail.

Six verbs: `host-config-set`, `host-config-remove`, `host-config-default`
(`--clear true` to unset explicitly; omission refuses rather than clearing),
`persona-binding-set`, `persona-binding-remove`, `execution-config`.

Access details stay off the chain: an entry is name + model + note. Endpoints
and keys belong to the host's own local configuration.

## Two execution policy settings

`execution.subagentPolicy` (`allowed`/`review-only`/`forbidden`) states whether
this workspace permits sub-agent fan-out — declarative, like `backup.cadence`,
because the engine never sees a subagent. `execution.independenceFloor`
(`none`/`verification`/`verification-and-risk`/`all`) is enforced: where the
floor covers a conference's type, `conference-close` refuses with
`CONFERENCE_INDEPENDENCE_REQUIRED` unless `--execution-form independent` is
declared. The declaration is a self-report, validated for presence and value
and never for truth — the same authorization-not-authentication ceiling the
gate machinery states about itself. With the floor at its default, nothing
changes.

## The portal grew an Execution surface

Configurations, defaults and bindings are managed in the portal, every setting
now leads with a human name in all five locales (the technical key stays
present — the CLI still speaks in keys), and every write shows the engine's own
receipt. A refusal arrives verbatim, never translated into a generic failure.

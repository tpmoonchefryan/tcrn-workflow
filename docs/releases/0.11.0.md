# TCRN Workflow 0.11.0

`0.11.0` is the INIT-020 engine-side release (`TCRN-CROSS-INIT-020`): the
engine gains a Postgres storage backend and the migration verb family that lets
a governed chain move between the file backend and Postgres. It is the recovery
path for `TCRN-CROSS-INC-072` — the VM engine now carries
`migration-execute` / `migration-verify` / `migration-rollback` so the switch
window (STORY-189) can run a five-chain migration.

## The change

- **Storage abstraction.** `StorageBackend` / `StoreBackend` interfaces in
  `packages/core`; the file backend is converged onto them for the workspace
  data plane and both stores (knowledge, artifact). File behaviour is
  byte-identical to `0.10.2`.
- **Postgres backend.** `PgBackend` / `PgStoreBackend` in the new
  `packages/pg-backend` workspace package, `pg` driver pinned at `8.22.0`
  (license / supply-chain / package-name / operating-cost review recorded in
  the source). A per-chain schema owns `events` / `metadata` / `markers`;
  append-only is enforced by GRANT + trigger; connection or verification
  failure fails closed.
- **Dual-backend equivalence gate.** Per-event bytes, head, and version are
  compared value-for-value between the two backends, with a mutation witness —
  a gate nobody can see go red is not a gate.
- **Migration verb family.** `migration-plan`, `migration-execute`,
  `migration-verify`, `migration-rollback`. Migration copies bound state; the
  workspace binding does not travel with the bytes, so a bypass copy is
  refused.
- **ADR `0004-postgres-storage-backend`.** Nine sections per STORY-171,
  including the roles/GRANT matrix, the DDL, and the equivalence criteria,
  each with a stated "what makes it red".

## Compatibility

- No verb, event-schema, or storage-version change to the file backend.
- File chains are byte-identical across `0.10.2` / `0.11.0` until a migration
  runs; the migration verbs are additive capability.
- `PROTOCOL_REASON_CODES` is unchanged.

## Release hygiene

`0.10.2` cut four manifests; this release adds a fifth workspace package
(`packages/pg-backend`). All five manifests, `FRAMEWORK_VERSION`, and the
`P8_VERSION` / `P8_TAG` constants are on one version, and the release carries an
annotated tag. The deployed VM copy is byte-identical to the local governed
copy, proven by the per-file digest ledger of `apply.mjs`.

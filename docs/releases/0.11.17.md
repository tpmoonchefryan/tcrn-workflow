# 0.11.17

A workspace stopped being readable because it had accumulated too much governed
prose. Not corrupted — accumulated. Every read verifies its views, both view
values canonicalised the whole record set into one string, and `canonicalJson`
fails closed past one MiB, so a chain that had done nothing but its job crossed
a ceiling and could no longer validate, list, show, or export. That is the
release: three ceilings that were reached by ordinary growth, and the gates that
had been measuring against references which moved underneath them.

## Views bounded by record count, not by prose length

The graph digest and the index each canonicalised `{projects, work}` whole. The
cross-project chain reached 1.55 MiB of canonical index at 611 records, 48% over
the limit, and only `status` still answered. Canonical form escapes non-ASCII, so
governed prose in Chinese costs about six times its UTF-8 size — most of the
weight was there.

Both are now linear in record count. The digest hashes each record and then the
vector of hashes; the index keeps identity and status verbatim and carries each
extension as the digest of its value (`tcrn.workspace-index.v2`). Detection power
is unchanged — any byte that changes inside any record still moves both — while
the index drops to 274 KB and headroom goes from *already over* to roughly 2,300
records. Existing workspaces take the new shape through `recover`.

One event landed while its command reported refusal: the annotate appended to the
log, the view could not be projected, and the CLI returned `INPUT_OVERSIZED` for
the whole call. Rebuilding the views brought the annotation back — the log is the
authority and views are derived — but a write that reports failure and lands
anyway is worth naming.

`export` is knowingly left out. It canonicalises the whole state by design, so a
large chain still cannot export; that wants chunking rather than digests.

## Gates that stop measuring against moving references

Three gates had frozen a reference that the tree then moved out from under:

- The portal coverage gate read its baseline from `git show HEAD:portal/index.html`
  and asserted the count equalled a literal. The same working tree measured 51
  roots before the commit that carried a portal rewrite into HEAD and 64 after, so
  committing turned the gate red on a change that added nothing unregistered. The
  roster is now a versioned file that fails closed in both directions.
- The doctor asked whether a launchd label was on duty when the chains already
  answer that question through `backup.cadence`. Declaring `manual` is the legal
  way to move backup to on-request, so an absent train is the declaration being
  honoured. The expectation is derived from the chain and relaxes only: an
  unreadable chain leaves the strict expectation standing and says so.
- An evidence block quoted a count measured against `HEAD:portal/locales.js`; once
  those keys were in HEAD the command could only read zero. It keeps its number
  and drops the verbatim claim it can no longer honour.

The practice is written down as the platform's gate-reference-stability
convention: a gate's reference must be a versioned roster, a chain declaration, or
a byte digest — never `HEAD`, never the wall clock, never a frozen constant paired
with a moving baseline. A pass must come from the subject's own declaration rather
than from a roster of known-acceptable exceptions.

## The harness is built at the workspace root

The manifest materialised a full harness into all five project roots, so which
hooks ran was a function of which folder happened to be open, inside directories
whose repositories are deliberately clean of them. It declares the container and
machine layers only now: 46 items become 23. The one surviving project entry is
not a materialisation — the engine repository commits its own sanitised CI
fixture, and it stays declared so a new doctor leg can tell an accounted-for
directory from a stray.

That leg is the other half. Every existing leg started from the manifest and asked
whether a declared thing was present; none started from the tree and asked whether
a present thing was declared. A pre-move container root kept a live harness for
four days, deciding what actually ran, and nothing could see it. The governed area
is derived from the manifest's own project roots — the container root, each
declared project, and the directories between them — so an unrelated project's own
configuration is not reported and the leg stays worth reading.

Because project settings do not inherit from a parent directory, the chain-write
refusal moves to the machine layer, where it holds wherever a session is opened.
That is a stronger guarantee than the per-project copies were.

## Portal

The switcher answered from a snapshot of the container taken at module load, so a
partition admitted afterwards stayed invisible until someone restarted the portal,
with nothing on screen to suggest the list was old. It reads the container now.

Three design defects, each measured rather than argued: a switch carrying both a
switch-control class and the text-field base measured 42×34 against a 42×24
contract; an explanation icon built out of a button component took its own grid row
and wore that component's hover box every time it spoke; and a tooltip raised inside
a sticky column could not paint above the table beside it, because sticky
positioning creates a stacking context and the column sat at `auto` alongside the
table's own sticky head.

A portal test that failed about one run in three is fixed by waiting for the
condition rather than for half a second. A gate that fails at random is not a
gate: a green run proves nothing and a red one gets dismissed.

## Upgrade

Existing workspaces need `recover` once per partition to take the new view shape;
reads refuse with `WORKSPACE_VIEW_STALE` until they do. Nothing in the event log
changes — views are derived and rebuildable, which is what makes the migration a
rebuild rather than a conversion.

# TCRN Workflow 0.10.0

> **Do not deploy 0.10.0.** Its placement of WSA-3 in the work-graph validator
> makes any existing chain that prematurely closed an Initiative fail replay.
> Fixed in 0.10.1, which moves the check to the write path. This page is kept
> as the record of the defect.

`0.10.0` is the twelfth accepted release. It adds a work-graph validation rule:
**an Initiative in the `done` state may not hold any live, non-terminal
descendant.** It is a minor release — it adds no public command, changes no
event-chain storage version, transforms no event, and alters no existing
receipt.

## The gap

The engine always had a strict work hierarchy (Initiative → Epic → Story →
Subtask) and a status machine with terminal states (`done`, `cancelled`). But
closing an Initiative was a discipline, not a rule: an operator could mark an
INIT `done` while its Epics were still `planned`, and the chain accepted it.
That is how a "closed" initiative carries open work without anything saying so.

The platform paid for this in a concrete way: an Initiative was closed with
three Epics still `planned` (its A2/A3 phases), and the close was premature.
The graph validator had no way to call it out.

## The change

`validateWorkGraph` now enforces **WSA-3**: for any `Initiative` whose `status`
is `done`, the whole subtree below it must contain no live non-terminal work.
A done Epic under the done Initiative with a still-active Story under it is red
too — the check is recursive over descendants, not just direct children. A
tombstoned (deleted) child is excluded: it holds no open work.

The refusal reason code is `WORK_GRAPH_ACTIVE_CHILDREN_OF_DONE_INITIATIVE`,
registered in `PROTOCOL_REASON_CODES`.

This is a **replay-level** check: a chain that violates WSA-3 refuses `validate`
and replay under 0.10.0, so a violating chain cannot be mistaken for clean. No
existing event schema changes; the rule applies going forward and to any replay.

## Compatibility

- No event-chain storage version change.
- No verb removed; no public command added.
- `PROTOCOL_REASON_CODES` grows by one entry — consumers that froze the exact
  set must update.
- A chain recorded under `0.9.0` that already has a done INIT with live
  children replays as `WORK_GRAPH_ACTIVE_CHILDREN_OF_DONE_INITIATIVE` under
  `0.10.0`; the fix is to terminalise or re-scope those children, not to
  downgrade the engine.

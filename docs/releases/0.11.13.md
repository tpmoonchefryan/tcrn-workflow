# 0.11.13

The portal ships inside this repository. Cloning the engine now gets you the
interface with it.

## Why it moved

The portal was built as a separate repository during INIT-022 — a shape decided
mid-execution rather than ruled on, and the Owner had authorised a self-contained
static page, not a second product. That separation cost three things at once: the
portal repository had no remote, so nobody outside this machine could obtain it;
its machine-level install sat under a directory write-protected for the trust
root, so updating it required working around a guard meant for something else;
and a portal and an engine released on separate tracks can disagree about which
version is running.

Living in `portal/` settles all three. The CLI the portal drives is resolved
relative to its own file — the engine it arrived with, never a guessed path — so
the two cannot drift apart.

## What this means for the checks

`portal/scripts/design-proof.mjs` and `portal/scripts/i18n-proof.mjs` compare the
shipped `tokens.css` and `locale-contract.mjs` against the design system. That
repository lives on the platform that authors the portal and on no user's
machine, so both **skip** when it is absent instead of going red. A gate that
fails where it was never meant to apply teaches people to ignore red.

`pnpm portal:test` is a sibling of `pnpm test`, never nested inside it: the
portal suite starts a real portal that spawns the real CLI, and `scripts/task.mjs`
holds an exclusive output session for the length of its run. See
`portal/README-TESTING.md`.

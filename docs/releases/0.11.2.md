# TCRN Workflow 0.11.2

`0.11.2` is the STORY-189 window rerun release: the Postgres backend now
segments by the workspace's own `segmentEventLimit` instead of a hardcoded
`SEGMENT_LIMIT=1024`, so a migrated chain keeps each canonical segment under the
protocol's 1 MiB bound. It is cut on top of `0.11.1` with `40c14bc`.

## The changes

- **PG backend segments by the workspace segmentEventLimit.** The PG backend
  hardcoded `SEGMENT_LIMIT=1024`, so a chain whose single 1024-event segment
  exceeded the 1 MiB canonical bound became unreadable after migration — the
  STORY-189 second attempt hit exactly this on TCRN-Design-System (v983,
  `WORKSPACE_MIGRATION_FUTURE` "canonical input exceeds one MiB"). The backend
  now reads `segmentEventLimit` from the workspace metadata row and lays out PG
  segments with it, falling back to the engine maximum when metadata is
  unreadable, matching the file backend's layout.
- **The segment-limit cache is invalidated on metadata write.** The migration
  probe enumerates target segments before the metadata row lands, which would
  freeze the fallback limit in the cache; the metadata write now resets the
  cache so a later read re-resolves the workspace's own limit.

## Compatibility

- No verb, event-schema, storage-version, or file-backend byte change. The CLI
  verb count stays 104.
- Chains migrated and verified green under `0.11.1` (Joi-Button, TCRN-TMS)
  re-verify green; the chains blocked on the 1 MiB bound (TCRN-Design-System,
  TCRN-AOS, cross-project) now migrate.
- Release hygiene unchanged: all five manifests, `FRAMEWORK_VERSION`, and the
  `P8_VERSION` / `P8_TAG` constants are cut on one version. Carries an
  annotated tag.

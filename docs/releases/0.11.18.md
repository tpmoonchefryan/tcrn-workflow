# 0.11.18

Two hosts ran this platform and only one of them was governed. Codex carried four
inert declaration files and no harness at all, under `approval_policy = "never"`
and `sandbox_mode = "danger-full-access"` — so on that host there was nothing
between an agent and the machine. That is the release: the harness became
something a host acquires by installing its adapter, and several gates that were
measuring the wrong place got aimed at the right one.

## Both hosts are under the harness

The harness had never been a thing the platform owned. It was hand-kept JSON
inside `.claude/settings.json`: four hooks, the control-tree deny rules, and some
environment. Nothing rendered it anywhere else, so "install the adapter" and "be
governed" were different events on Claude Code and only the first one had ever
happened on Codex.

There is now one roster, rendered per host, and it is keyed on **capability**
rather than on hook. Each capability states what must be true; each host states
the mechanism it uses to make it true. That distinction is what lets a check say
*this host is missing this guarantee* instead of the much weaker *this file is
absent*, and it is the only shape in which two hosts' different mechanisms for
one guarantee can be compared at all.

One capability needed a workaround, and it is recorded rather than glossed.
Claude Code states the control-tree write refusal declaratively in
`permissions.deny`; Codex has no such list, so there the same refusal is a
PreToolUse hook. A hook is weaker in three ways that are written down where they
are read: a hook that crashes lets the operation proceed where a deny rule would
not, so the guard contains nothing that can throw; Codex fires PreToolUse for
Bash, `apply_patch`, MCP and local function tools but not for hosted ones, and
that gap is real; and the guard deliberately ignores Bash, because every governed
read names the workspace it reads and a path rule over shell would refuse the
engine itself.

`platform-doctor` gains a coverage leg that is the rule written as a predicate: a
host with an adapter installed must have a complete harness. Conditional on the
adapter, so a machine that never installed Codex is not missing anything — and
with a governed way back to green, which is what separates a fair red from an
ornament.

Both hooks references were read rather than inferred. Codex and Claude Code agree
on event names, on the stdin payload, on the stdout contract, and on blocking by
exit 2 or `permissionDecision`; Codex's event set is a strict subset of Claude
Code's and contains every event this harness uses.

## A touched installation has a way back

`identityDigest` covers `mtimeMs` and `ctimeMs`, and `ctime` cannot be set —
`utimes` moves `mtime` and stamps `ctime` with the present moment. So one benign
touch of an installed adapter file was permanent: uninstall refused the mismatch,
install refused because `O_EXCL` found the target present, and every verb needing
an installation context went through the strict reader. Across 128 verbs there
was no repair. The only exit was deleting the files outside the engine — a
fail-closed design forcing an ungoverned act, which is the worst of both.

`adapter-rebind` and `claude-adapter-rebind` relax the identity comparison and
nothing else. Content must still hash to the recorded digest; containment,
realpath equality, link shape, special-file and read-time stability checks all
still run; the receipt is still admitted under its out-of-band authority. What
identity detects beyond content is *this file was touched*, not *this file is not
the one we installed*: different bytes are caught by content, link substitution by
`nlink` and `O_NOFOLLOW`.

The property that keeps the new read option from becoming a force flag by the back
door: a context read with identity drift tolerated is deliberately **not**
branded, so uninstall, rollback and activation refuse it exactly as before. A
test asserts it and a guard pins it in both adapters.

The doctor reports drift and does not decide on it. Observations sit beside the
verdict, so a chmod cannot turn the platform red — and until the rebind verbs
existed there would have been no governed way to turn such a red back to green,
which is how a gate becomes an ornament.

## Gates aimed at where nobody was standing

`pnpm preflight` ran a second copy of the P1 roster, and the copies had drifted by
two gates: `portal` and `no-sibling-dependency`. So the one world that proves this
repository stands up without its siblings was precisely the world not running the
sibling gate. Both now read one roster. Running the fuller list immediately found
a test that asserted a sibling is present — a test that needs a sibling to pass is
the dependency the gate exists to forbid — and a verification-map claim still
expecting a reason code from a renamed verb.

The stop-pact gate had been handed two fixed directories, the repository and its
parent. When the platform ruled that harness is built at the chosen workspace root
and archived the project-local copies, that pair began naming two places the
harness is not, and the gate read red on a channel that was demonstrably live.
Red-because-mis-aimed is worth no more than green-because-mis-aimed: both are a
gate reporting on somewhere nobody is standing. It discovers the root now, and
stops at the home directory, because the user settings layer is not a workspace.

## The MCP transport is retired

It derived every tool from the command catalog and held no logic of its own; all
126 catalog verbs were already `cli`, so no published contract changes; and the
authority contract it consumed is unchanged and exercised through the CLI. The
bundle keeps its `mcp` grant object, because dropping a required field of
`tcrn.operator-authority-bundle.v1` is a schema break rather than a cleanup.

Removing it took three guards' coverage with it, which the coverage gate could not
see: it compares test names and counts, and every count was satisfied. Mutation
testing caught it, and the two tests are restored against the surface that
remains.

## Waiting instead of sleeping

The portal's UI tests used a fixed 900ms in their shared loader, and three 700ms
sleeps after a fetch, as a stand-in for "the page is ready". Under load they read
the DOM before it was filled — in the full sweep and in preflight's isolated
clone, so not a local flake. The file already carried the lesson in a comment
above its own polling helper; the helper had been applied to one leg and not to
the loader every test goes through.

Waiting on in-flight requests rather than on an asserted field is the part worth
keeping: a test that waited for the field under test would turn a real regression
into a timeout instead of a readable difference. Where two cases render
byte-identically — deliberately, because a foreign contract must leak nothing —
there is no change to observe, so the settle signal is the fetch being answered.
The file is also faster than it was under the fixed budget.

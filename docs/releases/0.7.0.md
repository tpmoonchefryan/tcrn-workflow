# TCRN Workflow 0.7.0

`0.7.0` is the ninth accepted release. It closes two read-surface gaps that a
downstream cockpit filed against `0.6.0` (`TCRN-AOS-INC-004`,
`TCRN-AOS-INC-005`), and it is a minor release because it adds two public
commands and one field to an existing receipt.

It does not change the event-chain storage version, adds no required flag,
removes no verb, and still declares `supportedAosReleases: []`.

## The shape of both gaps

Neither gap was a missing feature. Both were reads that work on a small chain
and vanish on a large one, in a way that presents as absence rather than as
refusal — which is the worst way for a limit to express itself, because a
consumer cannot tell it from an empty answer.

`export` is the only read that returns external keys and advisory extensions,
and it refuses any workspace whose canonical form exceeds one MiB. Two of the
four chains on the platform that filed these already exceed it. So on those
chains:

- Every read that *did* work returned records identified only by id. A record id
  is a one-way digest of its external key, so a consumer could render a complete
  work tree and name nothing in it. The cockpit's actual workaround was to
  re-derive keys by brute-force digest match against the naming convention,
  which recovers conventionally-named records and leaves everything else
  permanently anonymous — 25 records out of 401, in the case that was measured.
- Positions and minutes had no workspace-scoped read at all. A conference could
  be listed, and its contents could not be reached. A deliberation holding
  fifteen arguments and one holding none rendered identically, and only the
  consumer's own defensive labelling ("positions not read") kept that from
  reading as a factual claim about the chain.

## Added

### `externalKey` in `work-list` summaries

The field the record already holds now travels with the summary. This costs one
field on a receipt and removes the entire digest-matching workaround.

### `conference-position-list` and `conference-minutes-list`

Workspace-scoped, optionally narrowed by `--conference-id`, and paginated with
`--limit` / `--offset` exactly like every other list verb. A large chain is now
read in windows instead of refused whole.

```
tcrn-workflow conference-position-list --workspace <ws> --limit 50 --offset 0
tcrn-workflow conference-minutes-list  --workspace <ws> --conference-id <id>
```

Both are authority-free reads, both appear in `commands`, and both are
projected as MCP tools on the same terms as their siblings.

## Compatibility

`work-list` receipts gain a field. A consumer that compares whole canonical
bodies against a stored fixture will see the difference; one that reads fields
will not. Nothing was removed, renamed, or made required.

## What this does not claim

- It does not make `export` paginated. `export` remains all-or-nothing, and the
  one-MiB refusal stands; what changed is that the families it gates are now
  reachable by other means.
- It does not add a cockpit dependency. The engine remains silent between
  queries and depends on no consumer.

# 0.11.15

A host now reads one named plan before it dispatches, and that plan is a table
from persona to model. Preset personas became editable without becoming
mutable. And every gate this release added carries a mutation that proves the
gate can go red.

## Subagent model plans

0.11.14 recorded a model per host configuration and pinned personas to it one
at a time. That shape was wrong in a way only use reveals: the thing an
operator wants to switch is not a model, it is a whole assignment table —
"today everyone runs the strong model, this week the implementers drop to the
cheaper one". So a plan is now `{host, name, defaultModel, assignments}`, where
`assignments` maps a persona name to a model and `defaultModel` catches every
persona the table does not name.

Choosing which plan is in force is a *setting*, not a property of the plan:
`execution.claudeCodeSubagentPlan` and `execution.codexSubagentPlan` are
reference-typed keys whose value must name an existing plan for that host. A
host with no plan set keeps its own default; the engine does not invent one.
Referential integrity runs both ways — setting a key to an unknown plan refuses
with `MODEL_PLAN_NOT_FOUND`, and removing a plan a key still points at refuses
with `MODEL_PLAN_IN_USE`.

Five verbs: `model-plan-set`, `model-plan-assign`, `model-plan-unassign`,
`model-plan-remove`, `model-plan-list`. The 0.11.14 write family
(`host-config-*`, `persona-binding-*`) is retired from the catalog; its events
still replay, and calling a retired verb now names its replacements rather than
failing blankly.

## Presets you can edit, and un-edit

The eight reference personas are compiled data — they ship with the engine and
they are the same on every install. Making them editable therefore could not
mean changing them. It means an overlay: `persona-preset-override` records the
fields you changed as a chain event, `persona-remove` records a tombstone, and
the read face composes base + overlay − tombstone. `persona-preset-restore`
removes the overlay, whole or one field at a time, and the factory value is
always readable underneath because it never went anywhere.

A name is an identity, so a name cannot be edited — for presets and custom
personas alike, and a custom persona may not take a preset's name even after
that preset has been tombstoned. The content is prose now
(`mission`, `refusals`, `authorityBoundary`, `contactWhen`, `requiredInputs`,
`deliverables`, `successCriteria`), matching the fields the compiled personas
already carried; the earlier free-form `prompt` field is gone, and events that
carry it still replay.

## A read-only vocabulary

`vocabulary` publishes the closed sets the engine actually enforces — roles
with their semantics and whether `review-only` can dispatch them, conference
types with which independence floors cover them, hosts, execution forms, and
the enum settings with their allowed values and control types. It derives from
the same constants the enforcement paths use, so a consumer cannot drift from
the engine by copying a list into its own source.

## The portal, rebuilt

Five pages under one grammar: a dashboard that reports state, and four
management pages that edit it. Writes still go through the public CLI and still
return the engine's own receipt; what changed is that the surfaces reporting
state no longer smooth over failure. The health card reddens when a read fails
instead of staying green with stale contents. The engine version comes from the
engine. The receipt chip shows `✓v<N>` or the refusal's reason code and opens
the full receipt.

## Gates that can fail

Four gates arrived with a mutation apiece, and the mutation is part of the
suite rather than a one-time demonstration:

- **UI presence** parses rendered DOM and asserts each component exists, is
  interactive, and changes state when used. Deleting a component, unwiring the
  receipt chip, or leaving the chip stale each turns it red.
- **i18n contract** compares whole locale tables, not just newly added keys, so
  a translation that regresses to English is caught by name rather than hidden
  under a count.
- **Coverage conservation** reads a checked-in baseline that must name every
  test file in the repository; an unregistered new test file is itself a
  failure, and assertions cannot be emptied out of a file whose test names
  survive.
- **Verbatim evidence** re-executes the commands quoted in evidence documents
  and compares their output byte for byte.

`pnpm verify:portal` runs the portal train, and CI runs it — with the workflow
file asserted from `scripts/task.mjs`, so removing the step from CI turns the
verify train red.

# TCRN Workflow 0.11.1

`0.11.1` is the STORY-189 window rerun release: two fixes to the migration verb
family that make the five-chain file→Postgres switch window runnable on real
chains. It is cut on top of `0.11.0` (INIT-020) with `d37e887` and the two
fix commits below.

## The changes

- **migration-verify compares full per-event canonical bytes.** The `0.11.0`
  verify criterion flattened segments to per-event `eventHash` so verify
  tolerates the file backend's `segmentEventLimit=64` vs the PG backend's
  `SEGMENT_LIMIT=1024` layout difference (the STORY-189 first-attempt false red
  on Joi-Button). But the PG backend reads `event_hash` as stored, never
  recomputed, so comparing only the stored hash misses a target whose
  `payload`/`payload_hash` was tampered while its `event_hash` was left stale —
  the STORY-178 red-leg test ("a tampered PG payload_hash turns verify red")
  went green on that tamper. Verify now compares the canonical JSON of each
  event field-by-field: layout-independent, and a tamper of any field is red.
- **Migration CLI exits instead of hanging.** `migration-execute` / `-verify` /
  `-rollback` open a PG client per invocation; a live client kept the event
  loop alive and the CLI hung after completing. The close helper also invoked
  `close()` detached, so `this.client` was undefined — it threw, masked the
  migration result, and left the sibling backend unclosed. The CLI now calls
  `close()` bound to `this` and swallows close failures, so the process exits
  and the migration outcome survives.

## Compatibility

- No verb, event-schema, storage-version, or file-backend byte change. The CLI
  verb count stays 104.
- `migration-verify` is stricter about per-event bytes than `0.11.0`; a chain
  whose migration was verified green under `0.11.0` still verifies green.
- Release hygiene unchanged: all five manifests, `FRAMEWORK_VERSION`, and the
  `P8_VERSION` / `P8_TAG` constants are cut on one version. Carries an
  annotated tag.

# TCRN Workflow 0.11.9

`0.11.9` is the INIT-022 pre-pin release candidate. It carries the first-class
settings surface, the template admission mechanism, and the adapter baseline —
the three engine changes the pre-pin batch found were needed before the engine
could be pinned.

Settings become a first-class, machine-readable surface. `settings-catalog`
returns the registered keys with their type, layer, current and default values;
`settings-set` writes one through a governed path with compare-and-swap against
the live head and returns a receipt carrying the chain version and receipt
digest. The key set is closed on purpose: a key exists because the engine
consumes it, so a deployment configures values while the registry itself stays
the engine's to define.

Template admission separates the mechanism from the genre. `template-admit`
brings a template under digest and owner authorization; `template-validate`
checks a candidate without admitting it. What a record must contain is data the
engine admits rather than a constant compiled into it, so a project can carry
its own genre without forking the engine, while the base contract stays where it
cannot be edited by the party it constrains.

The adapter baseline names the hooks the machinery needs to run and holds them
to that name, without claiming anything about hooks a user installs. The
validator speaks about the baseline and stays silent about the rest, so a user
region and the governed region can share one host without either editing the
other.

The release bytes are ready for the separately authorized tag and publication
operation; no AOS compatibility pair is claimed.

## Compatibility note

The settings and template surfaces are additive: a chain written by an earlier
build reads unchanged, and a record carrying no template binding is read under
the contract that was in force when it was written rather than retroactively
judged against a newer one. Readers and writers of a chain that uses the new
surfaces must run a compatible build.
